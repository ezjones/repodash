# RepoDash TUI and herdr plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `repodash -tui`: the web Grid as a Bubble Tea terminal UI (compact cards, right details panel, vim keys, mouse) that jumps to or creates the repo's herdr workspace, plus a `herdr-plugin.toml` that opens it as a popup.

**Architecture:** The TUI runs inside the existing binary and reuses `scanAll`, `agentState`, `cfg`, the notes folder and the issues fetcher in-process; it needs no web server. Jumping reuses `openInHerdr` / `openInTmux` after a new side-effect-free `pickMux` decides which multiplexer and whether a tab already exists. Issues gain an exact open count and a short open list, and are cached on disk so a freshly opened popup shows them at once.

**Tech Stack:** Go 1.26 toolchain, `charm.land/bubbletea/v2` (v2.0.x), `charm.land/lipgloss/v2` (v2.0.x), `gh` CLI, herdr 0.9.x.

**Spec:** `docs/superpowers/specs/2026-10-24-tui-design.md` (read it with this plan; the card picture, key table and settings list live there and are not repeated here).

## Global Constraints

- `CGO_ENABLED=0 go build -o repodash .` must produce a static binary; `gofmt -l .` and `go vet ./...` print nothing; `go test ./...` passes after every task.
- Dependencies: Charm's TUI libraries only (Bubble Tea, Lip Gloss, Bubbles if useful), used only by `tui*.go`. Server code stays standard library. Raising the `go` line in `go.mod` is allowed.
- Read-only toward repos: git through the existing `git()` helper (`GIT_OPTIONAL_LOCKS=0`, `core.fsmonitor=false`), never fetch.
- Public project: no real repo names, hostnames or home paths in code, tests, docs or commit messages. Test names use placeholders (`my-app`, `api-server`, `demo`). Before every commit: `ls ~/gitrepos | while IFS= read -r n; do git diff --cached | grep -qF -- "$n" && echo "HIT: check diff"; done` (ignore a hit for `repodash` itself).
- Never act on the owner's real tmux or herdr: tests use fakes; tmux manual checks use a throwaway server (`env -u TMUX TMUX_TMPDIR=$S/tmux ...`); a real herdr popup check happens only in Task 6 with the owner's go-ahead. Never `tmux kill-server`.
- The web page, `/api/*`, `-json` output (apart from the two new issue fields) and existing flags behave exactly as before.
- Always dark palette in the TUI; status colours from `statuses.<k>.darkColor`, accent from `colors.accentDark`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Zero repos / empty filter / search with no match**: grid shows a one-line "No repos match" and the panel is empty; no index-out-of-range on Enter, `G`, mouse click. Test in Task 4.
2. **Terminal narrower than one card plus the panel, or resized mid-run**: panel hides, cards keep ≥1 column, selection stays visible after resize. Test in Task 5.
3. **Repo vanishes or reorders between scans** (folder deleted, sort by activity changes): selection follows the same repo name, falls back to index clamp. Test in Task 4.
4. **`gh` missing or logged out, or issue cache file corrupt/absent**: TUI still opens instantly; issues just don't show; a corrupt cache is ignored, not fatal. Tests in Task 2.
5. **Jump fails** (no herdr/tmux server, command error): message line shows the error, TUI keeps running, popup does not close. Test in Task 4.
